# Releasing the HydroNode CLI

Channels: GitHub Releases (archives, `.sha256`, build provenance), shell and PowerShell installers,
Homebrew tap `TexhFexLabs/homebrew-tap`, winget `TexhFexLabs.HydroNode`, Snap `hydronode`. No npm, no crates.io.

## Setup (done 2026-11-18)

| Channel | State | Where |
|---|---|---|
| GitHub Releases | archives, `.sha256`, build attestations | `release.yml` (dist) |
| Homebrew | tap `TexhFexLabs/homebrew-tap`, formula `hydronode` | secret `HOMEBREW_TAP_TOKEN` (fine-grained PAT, contents write on the tap only, expires 2027-11-19) |
| Snap | live since 0.1.0 (amd64 rev 1, arm64 rev 2), channel `stable` | secret `SNAPCRAFT_STORE_CREDENTIALS` (`snapcraft export-login --snaps=hydronode --acls=package_access,package_push,package_update,package_release`, expires 2027-11-18), variable `SNAP_ENABLED=true` |
| macOS signing | Developer ID Application, from 0.1.2 | secrets `CODESIGN_CERTIFICATE` (base64 .p12), `CODESIGN_CERTIFICATE_PASSWORD`, `CODESIGN_IDENTITY` (`Developer ID Application: … (TEAM)`); `macos-sign = true` in `dist-workspace.toml`, hardened runtime. Certificate valid until 2027-12-18 |
| winget | not yet | below |

Snap renew (needs a terminal, it asks for the Ubuntu One login):

```bash
snapcraft export-login --snaps=hydronode --channels=stable,candidate,beta,edge \
  --acls=package_access,package_push,package_update,package_release --expires=<date> ~/snap-creds.txt
gh secret set SNAPCRAFT_STORE_CREDENTIALS -R TexhFexLabs/hydronode-cli < ~/snap-creds.txt && rm ~/snap-creds.txt
``` `hn` as a short command needs
the store's auto-alias: ask on forum.snapcraft.io (category store-requests), until then
`sudo snap alias hydronode.hn hn`. The plug `password-manager-service` is not connected automatically;
without it the CLI keeps tokens in its private file (0600): `sudo snap connect hydronode:password-manager-service`.

macOS signing renew (Account Holder only, before 2027-12-18):

1. Keychain Access › Certificate Assistant › *Request a Certificate From a Certificate Authority…*, saved to disk.
2. developer.apple.com › Certificates › **+** › *Developer ID Application* › G2 Sub-CA › upload the CSR,
   download the `.cer` and open it (it pairs with the key from step 1).
3. Export and set the secrets (macOS asks to allow the key export):
   ```bash
   security export -k ~/Library/Keychains/login.keychain-db -t identities -f pkcs12 -P "<tmp>" -o all.p12
   # keep only the Developer ID identity, repack with 3DES/SHA1 (what `security import` on the runner reads)
   base64 -i devid.p12 | gh secret set CODESIGN_CERTIFICATE -R TexhFexLabs/hydronode-cli
   gh secret set CODESIGN_CERTIFICATE_PASSWORD -R TexhFexLabs/hydronode-cli
   gh secret set CODESIGN_IDENTITY -R TexhFexLabs/hydronode-cli    # exact name from security find-identity
   ```
   Delete the .p12 files afterwards. Signed binaries keep "Always allow" in the keychain across updates;
   unsigned ones ask again after every update. Not notarized (dist does not do that); Homebrew, the install
   scripts and Snap do not set the quarantine flag, so Gatekeeper does not ask.

winget: after the first release, `packaging/winget/render.sh <version>`, check with `winget validate` (and
`winget install --manifest <dir>` on Windows), open the PR to `microsoft/winget-pkgs`. Once merged: secret
`WINGET_TOKEN` (classic PAT, `public_repo`, for the fork), variable `WINGET_ENABLED=true`; from then on
`packages.yml` opens the PR for each release.

## Every release

1. Version in `Cargo.toml` (workspace), `CHANGELOG.md`, commit, PR, CI green, merge.
2. Signed tag: `git tag -s vX.Y.Z -m "HydroNode CLI X.Y.Z" && git push origin vX.Y.Z`.
3. `release.yml` builds all targets, attests them, creates the GitHub release and updates the Homebrew formula.
   `packages.yml` follows the finished Release run (a release made with `GITHUB_TOKEN` fires no `release` event)
   with Snap (amd64, arm64) and winget. Rerun by hand: Actions › Packages › Run workflow with the version.
4. Check: `brew install texhfexlabs/tap/hydronode`, `gh attestation verify <archive> -R TexhFexLabs/hydronode-cli`,
   on a Mac `codesign -dv --verbose=2 "$(which hydronode)"` names the Developer ID.

## Changing release.yml

It is generated by `dist` 0.34.0 and then hand-edited (`allow-dirty = ["ci"]` in `dist-workspace.toml`):
actions pinned by commit SHA, `contents: write` only for `host` and `announce`, the dist installer checked by
SHA-256, the `CODESIGN_*` secrets only in the env of the `apple-darwin` builds. After `dist generate`, apply these again and run `actionlint`.
